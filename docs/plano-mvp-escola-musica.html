Stack Tecnológica

Antigravity (Google)
IDE de desenvolvimento — ambiente, terminal, preview e deploy integrados
Next.js 15 + TypeScript
Framework fullstack com App Router — Server Components, Server Actions e Route Handlers
Tailwind CSS + shadcn/ui
Estilização utilitária + componentes prontos (tabelas, forms, badges, modais)
Notion API · @notionhq/client
Banco de dados visual — token seguro no servidor via Server Actions, nunca exposto no cliente
Vercel
Deploy contínuo direto do repositório — plano gratuito suficiente para o MVP
Por que Next.js 15?
Chamadas à Notion API ficam em Server Actions — token nunca exposto. Server Components aceleram listagens. Deploy na Vercel é trivial.

Pontos de Atenção

⚠ Limite da Notion API

A API do Notion tem rate limit de 3 req/seg. Para o MVP isso é suficiente, mas evite fazer muitas queries simultâneas. Implemente cache simples nas listagens que não mudam com frequência.

✓ Aulas recorrentes

Aulas fixas semanais podem virar um gerador que cria as entradas no Notion em batch (ex: próximas 4 semanas), ao invés de repetir infinitamente. Facilita muito edição e cancelamento.

ℹ Geração de cobranças

Para o MVP, a geração de cobranças mensais pode ser manual (botão "gerar mensalidades do mês"). Automação via cron job pode ser adicionada na v2 depois da validação.

✓ Notion como backoffice

Uma vantagem do Notion como DB é que você mesmo pode editar dados diretamente no Notion para correções rápidas sem precisar de tela de admin para tudo. Agiliza muito o MVP.

⚠ Autenticação simples

Para o MVP, um único usuário admin (dono da escola) é suficiente. Multi-tenancy e perfil de professor podem ser adicionados na v2 após validar os fluxos principais.

ℹ Futuras integrações v2

Pós-MVP vale considerar: geração de boleto (Asaas/Pagar.me), WhatsApp para cobrança automática, portal do aluno para ver suas aulas, e relatórios em PDF.
